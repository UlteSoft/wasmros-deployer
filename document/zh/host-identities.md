# 宿主身份所有权

独立 cgroup 和命名空间不能让复用 Linux UID/GID 变得安全。凭据仍影响信号、
procfs 和文件访问。`run`、`resume` 及监督器 API 会在创建工作进程前，在宿主共享
的 `/run/wros-ownership` 中登记所有最终 UID/GID。预检、审核、授权和服务文件
生成命令不会占用身份。

登记目录由部署器在 root 拥有的 `/run` 下以 0700 创建；记录与准入锁为 0600。
符号链接、非普通文件、多硬链接、错误所有者、权限或损坏记录都会导致拒绝。
每批最多 256 个独立 UID/GID，数字必须规范、非零，且不是全一无效值。

所有者绑定准确的工作组父路径和部署名称。全部现有记录检查通过后，才写入新
记录。短期全局锁串行化登记，各身份的非阻塞锁在清理旧组和消耗恢复授权前就
必须取得，并持有到监督和停机结束。另有部署级锁，阻止同一 cgroup 的旧配置
通过改用其他 UID/GID 绕过排他检查。第二份旧审批不能先清理活着的原部署。冲突
只拒绝新部署，不向原有部署发送信号；身份互不冲突的部署可以并行运行。登记
描述符在工作进程执行时关闭，不交给 Wasm 或外置服务。

管理进程崩溃或正常退出不会删除所有者记录。即使锁已经释放，其他部署器也
不能自动接管。原部署可重新登记，但仍须分别通过已批准权限、旧 cgroup 清理
和重启检查。新增接入应由原部署器管理，不进行跨部署器移交。

记录在启动前同步，并包含所有者、身份和校验和；校验和不等于授权签名。写入
失败可能留下部分保留或不完整记录，此时拒绝启动，不把它们当作空闲身份。
程序不自动删除或修复记录。管理员必须确认全部相关进程停止后，才能离线修复。

通常 `/run` 在整机重启时清空；平台若保留它，记录也会保留，不自动过期。共享
宿主身份的部署器必须看到同一个登记目录，并使用一致的宿主 UID/GID 和 cgroup
命名空间。不能让各容器使用互不相见的私有登记目录。平台仍须为 WROS 预留
专用系统身份；此机制不能阻止非托管进程或管理员使用同样的凭据。

显式 `run` 启动的只读原生驱动与 VM 在同一事务中保留各自的 UID/GID。登记只
发生在准入路径，且独立于设备过滤、物理设备租约、跨主机所有权和运动授权。
测试覆盖 UID/GID 分别冲突、独立部署并行、管理进程死亡、原所有者恢复、损坏
记录、链接、访问权限和描述符继承；完整内核测试在 QEMU 中运行，不构成物理
安全认证。

组合准入 API 还支持 128 个确切设备键，与 UID/GID 在同一事务中登记。
设备别名、原归属保留及独立 BPF 约束见[设备隔离说明](device-isolation.md)。

# 检查恢复模块

在把恢复模块交给守护进程之前，可以先运行部署器的本地预检。

```sh
wros-deployer inspect-recovery candidate.wasm
```

命令从同一个普通文件描述符读取候选模块，对实际校验的字节计算 SHA-256，并报告入口函数、线性内存范围和静态指令数。运行预检只需要文件读取权限。预检授予的宿主操作权限为零。当前部署继续执行已审核的原生冷启动策略。

## 允许的模块

验证器按最初的 WebAssembly MVP 规范检查指令、操作数类型、索引、函数体和分支。模块必须声明一个私有的 32 位内存并给出最大页数。入口可以是标准 start 段或唯一导出的 `_start` 函数，签名为 `() -> ()`。同时声明两个入口会被拒绝。当前不开放宿主导入，因此 WASI、外部表、恢复实验接口和其他模块函数均无法接入。线程、私有 MTE 指令、组件二进制和组件类型元数据也会被拒绝。

| 资源 | 上限 |
| --- | ---: |
| 模块文件 | 65,536 字节 |
| 私有线性内存 | 16 个标准页，共 1 MiB |
| 函数、函数类型 | 各 128 个 |
| 每个函数类型的参数 | 32 个 |
| 每个函数声明的局部变量（参数除外） | 256 个 |
| 所有函数体的静态指令总数 | 8,192 条 |
| 控制栈嵌套（包含函数自身） | 64 层 |
| 全局变量 | 64 个 |
| 可选的私有表 | 最多 256 项，必须声明最大值 |
| 元素段、数据段 | 各 128 个 |

循环和递归都属于 MVP。静态指令预算限制校验工作量，运行时仍需要指令计量、调用栈和值栈限额，以及独立执行的超时控制。通过预检的程序在执行时仍可能陷阱退出。预检不会执行模块，也不会触发重启、热更新或运动。

## 实现与复测

部署器默认启用编译选项 `recovery-preflight`，使用仓内的 wasmparser 按 MVP 特性掩码验证。采用 `--no-default-features` 编译可完全移除该验证器依赖。未来独立的最小守护进程需要单独审查其纯 MVP 解释器和依赖。恢复模块宿主 ABI 仍在验收阶段。

在约定的 cgroup 内执行 `tests/recovery_preflight.py`，用 `--deployer` 指定部署器，用 `--output` 指定本项目 `.tmp` 中尚不存在的目录。脚本使用 WABT 的汇编器和验证器作独立对照，并用官方解释器执行正向样本与主动触发陷阱的对照样本。测试还覆盖入口选择、实际线性内存读写、导入与扩展拒绝、资源边界、畸形输入及特殊文件。WABT 仅用于测试。

# 设备归属与内核访问控制

每个 VM 启动前必须安装 Linux cgroup v2 设备 BPF 规则。内核不支持、验证器拒绝、
祖先规则不兼容或安装失败都会拒绝执行，不退回无限制访问。此权限属于部署器，VM
不会获得 BPF、cgroup 管理或进程创建接口。

VM 运行时固定允许字符设备 1:3（`/dev/null`）读写，1:5、1:8、1:9（`zero`、
`random`、`urandom`）只读。其他设备打开和全部 mknod 均拒绝。审核与执行时用
INFO 复述。这不是 Wasm 导入或 WASIp1 路径授权，应用仍需单独审核接口及资源。
物理设备应由隔离的外部驱动访问。

## 检查设备不打开硬件

`devices::Device::inspect` 用逐层固定的 `O_PATH` 描述符检查确切的 `/dev`
绝对路径，不进行可触发硬件的读写打开。祖先目录必须属于 root，组和其他用户不可
写。符号链接、空组件、点或父目录组件、非设备文件、已删除节点及过长路径均拒绝。
最终节点必须属于 root；by-id 别名由受信平台配置层解析为实际节点。

归属键是字符/块设备类型、主设备号、次设备号；同设备的不同节点别名共用一个键。
`revalidate` 拒绝 inode 被替换，即使设备号相同。热插拔可能复用设备号而不改节点，
所以不能据此证明真实机器人序列号、总线身份或固件安全状态。平台还须独立确认已
批准的硬件与安全状态。网络控制设备需要另外的归属与网络策略。

## 跨部署器保留原归属

`ownership::claim_with_devices` 在一次准入事务中登记最终 UID/GID 与设备键，
使用 root 私有 `/run/wros-ownership`。每批最多 256 个 UID/GID、128 个设备记录；
同批重复键或同设备别名拒绝。归属绑定确切 cgroup 父目录与部署名称。原部署器退出
或崩溃释放锁也不允许另一部署器接管；新客户端必须经原部署器接入。正常关闭不删除
归属记录。

`Reservations::check_devices` 检查管理进程、归属、键和固定节点；fork 句柄副本
不是新部署权限。原部署器恢复仍需通过人工批准、安全状态、旧进程清理和恢复策略。
归属不代表运动授权。`/run` 通常随开机清空，重新取得归属也不会恢复运动权限。

所有管理器必须共用受保护的主机登记表与设备号空间。容器私有 `/run` 无法协调同一
物理设备。登记不能限制不受管理的特权进程，内核过滤是另一层约束。root、内核、
物理身份映射和受信命令接收端仍在信任边界内。

## 固定内核策略

`devices::Policy` 支持 0 至 128 条确切设备的只读、只写或读写规则。重复键拒绝，
不隐式合并权限。不接受通配符、mknod、自定义字节码、map 或 helper。生成程序最多
1,033 条指令，只含向前分支，由 Linux 准入前验证。UAPI 显式处理五 ABI 对齐填充。

`attach_empty` 只用于调用者独占管理、受保护的空 cgroup v2 domain。已有程序拒绝，
不替换、不用 `ALLOW_OVERRIDE`，不能扩大祖先限制。同组并发 root 管理不在契约内。
关闭程序 FD 不解除规则；清空并删除 cgroup 才结束其生命周期。管理器崩溃不会让旧
进程自动扩大权限。

依据 Linux [设备控制器](https://docs.kernel.org/admin-guide/cgroup-v2.html#device-controller)
语义，它检查设备打开与节点创建，**不撤销已有 FD**、不逐条过滤 ioctl、不验证厂商
协议，也不证明物理安全停机。启动必须清理未授权继承 FD，初始化通道拒绝多余 FD，
驱动设备句柄不能进入 VM。具体命令权限与仲裁必须由厂商代码之外的受信接收端管理，
再次运动仍需独立安全状态和人工确认。

## 测试与接入边界

`tests/qemu_devices.py` 用 Linux 伪设备完成 21 项真实内核测试：默认拒绝、独立
读写、规则上限、父子与兄弟组、已有规则保护、关闭 FD 后规则保持、非法/非空目标、
别名、inode 替换、管理器崩溃、原归属保留、损坏记录和句柄清理。另有明确测试证明
已有设备 FD 不会被撤销。2 GiB 离线来宾位于现有 64 GiB 测试组内，不使用宿主
mknod、BPF 安装、特权命令、磁盘、共享目录、网络或物理设备。

独立的 37 项监管器内核测试在非特权替身和实际签名 VM 下覆盖设备限制、独立 cgroup、
放置、资源耗尽与恢复。五 ABI 用户态测试验证字节码、布局和归属；QEMU-user 映射
到用户拥有的根目录时正确拒绝。正常设备准入和 BPF 必须由完整内核测试验证。
QEMU 耗时不作为原生硬件性能结论。

`tests/vendor_unitree_qemu.py` 编译 Unitree SDK 2.0.2 中未修改的
HelloWorld 源码，并使用同一套官方原生 SDK、IDL 和 DDS 库构建 Go2
`LowState` 遥测用例。测试器用临时 Ed25519 密钥签署来宾中可执行文件和库的
摘要清单。来宾先验签、核验文件摘要，再以不同的非 root 用户在两个独立 cgroup
中启动进程。测试同时验证修改后的清单被拒绝，以及两种消息都可经来宾回环传输。
[Unitree SDK 源码](https://github.com/unitreerobotics/unitree_sdk2/tree/811bc77cdcffb4691d4b40172f9a57857bf6cffb)

显式 `run` 可以启动单 VM 的独立只读 ELF 适配器，适配器和 VM 使用独立 cgroup
与宿主身份。驱动子组拒绝实际设备和设备节点创建。物理设备身份、安全停机和
自动恢复仍需联动。参见[原生适配器和加密交付](attachment-provisioning.md)。
